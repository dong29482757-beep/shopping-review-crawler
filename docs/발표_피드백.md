# 발표 피드백과 대응

## 받은 피드백

발표 후 가장 크게 들은 평가는 이거였다:

> "모델을 만들긴 했는데, 실사용성이 없다. 모델을 만들라니까 만든 느낌이다."

ML(TF-IDF+로지스틱회귀)과 DL(numpy 신경망, LSTM, KoELECTRA)까지 비교 실험을
하고 정확도(ML 0.738 / DL 0.762)를 뽑아내긴 했는데, 그게 서비스에서 실제로
뭘 바꾸는지가 없었다는 지적이다. 정확한 지적이었다.

## 1차 대응 (피드백 받은 직후) — 절반만 고친 상태였다

처음에는 이렇게 고쳤다:

- "리뷰 텍스트를 직접 입력하면 감성을 분류해주는" 데모 탭을 없앴다.
  ("이미 써본 리뷰를 직접 타이핑할 이유가 없다"는 게 이유)
- 학습된 모델(`ml_logreg.joblib`)을 538,774건 전체 리뷰에 한 번 돌려서,
  "이 리뷰가 별점과 내용이 일치하는지"를 계산하고 **"리뷰 신뢰도"** 라는
  지표로 상품 리포트에 노출했다. 신뢰도가 낮은 상품엔 경고 문구도 띄웠다.

여기까지 하고 "모델을 평가용 실험에서 실제 서비스로 옮겼다"고 정리했는데,
다시 점검해보니 **이것도 절반만 고친 거였다.** 리뷰 신뢰도는 화면에 보이는
"참고 배지" 하나였을 뿐, 사용자가 실제로 보는 핵심 숫자 — 속성별 장단점
%, 추천 순위 — 는 모델과 전혀 상관없이 100% 정규식 키워드 매칭(`absa.py`)
으로만 계산되고 있었다. 모델 점수를 옆에 하나 더 보여주는 것과, 모델이
결과를 바꾸는 것은 다른 일이다.

## 2차 대응 (이번) — 모델이 핵심 숫자를 직접 바꾸도록

`precompute_model_sentiment.py`가 리뷰 단위로 "모델이 본 감성"과 "별점
기반 라벨"의 일치 여부를 `review_match_flags.csv`에 저장하도록 바꾸고,
`precompute_absa.py`(장단점/추천 점수를 계산하는 파이프라인)가 이 파일을
읽어서 **모델이 "별점과 내용이 안 맞는다"고 판단한 리뷰를 장단점 집계에서
실제로 제외**하도록 바꿨다.

즉:

- 이전: 모델 결과 = 화면 한쪽에 표시되는 참고용 배지. 안 봐도 서비스는 똑같이 동작함
- 이후: 모델 결과 = 사용자가 보는 "이 제품 보습 92% 긍정" 같은 숫자 자체를 만드는 데 직접 쓰임. 모델 없이는 그 숫자가 다르게 나옴

화면에도 "모델이 신뢰도가 낮다고 판단한 리뷰는 분석에서 제외했다"고
명시해서, 모델이 실제로 한 일이 무엇인지 숨기지 않고 보여준다.

**실행 결과**: 53만 건 재계산 후, 534,803건 중 50,806건(9.5%)이 모델에
의해 제외되고 483,997건으로 장단점/추천이 다시 계산됐다 — 앞서 측정한
리뷰 단위 불일치율(9.5%)과 정확히 일치한다.

## 정직하게 남는 한계

- 모델이 하는 일은 "노이즈가 있는 리뷰를 걸러내는 데이터 품질 필터"다.
  속성별 감성 자체(보습이 좋다/나쁘다 판단)는 여전히 규칙 기반(`absa.py`)
  이다 — 모델이 아예 속성 단위 분류를 학습한 게 아니라서, 전면 교체는
  현재 데이터로는 무리라고 판단했다.
- "제외"라는 방식이 거칠 수 있다. 정말 모델이 틀렸을 수도 있는데 무조건
  빼버리는 거니까. 더 정교하게 하려면 confidence 기반 가중치 같은 걸
  추가로 고려할 수 있다.
- 그래도 이번 변경으로 모델의 존재 여부가 실제 출력값의 차이를 만든다 —
  "모델을 빼도 서비스가 똑같이 돈다"는 이전의 가장 근본적인 문제는
  해결됐다.
